Draw the layout of one slide as a short element list; a fixed builder turns it into a real PowerPoint mockup.

Look at the rendered slide: {png}
Extracted regions of the same slide: {regions}
(index "i", type, normalised box {{x, y, w, h}}).

Write ONE JSON object to {out}
It must validate against {schema}:
  {{"version": 2, "elements": [ {{...}}, {{...}} ]}}   5-20 elements, never more than 25

Draw from the picture: decide every element and estimate its box by eye. Then, only where an element clearly matches
one extracted region (the same thing in the same place), add region_ids with that region's "i": its box snaps to the
exact region (several ids snap to their union, e.g. one text block split over lines). Where no region clearly matches,
leave region_ids out and keep your box. Give a box for every element either way.

Each element has only these fields:
  kind         one of: {kinds}
  shape        one of: {shapes}
  box          [x, y, w, h] as floats 0-1 of the 16:9 slide: top-left corner, width, height (x + w <= 1, y + h <= 1)
  points       optional, for polygon / line / connector only: up to 12 [x, y] points, floats 0-1 of the slide
  dashed       optional, true when the outline or line is dashed
  emphasis     optional, one of: {emphases}; it sets the real size: "hero" is the one element the eye lands on
               first (a hero number is drawn huge), "strong" a secondary accent
  region_ids   optional: indices "i" of the extracted regions this element clearly matches (see above)
  parent       optional: index (from 0) of the container this element sits inside; containers are band, strip,
               panel and card, and a parent is always listed before its children (cards inside a panel, text in a card)
  framed       optional, text kinds and takeaway only: true when the text sits inside a visible outline or box
  fill         optional, containers only: one of: {fills} (how dark the container's background is)
  chart_type   charts (kind "chart") only, required: one of: {chart_types}
               (bar = horizontal bars, column = vertical bars, stacked_bar = horizontal stacked)
  series       optional, charts only: 1-6, the number of bar groups / lines / stacked segments / donut rings
  categories   optional, charts only: 1-12, the number of bars per series / line points / slices
  rows, cols   tables (kind "table") only, required: 1-20 each, count the visible grid
  header_row   optional, tables only: true when the first row is a header
  arrow_style  arrows (kind "arrow") only: one of: {arrow_styles} (line = a thin line with a head, block = a fat
               arrow shape, give its direction with shape arrow_*; chevron = a chevron shape)
  head         optional, connectors and line arrows: one of: {heads} (default end)
  from, to     optional, connectors only: indices (from 0) of the two elements the connector joins

Identify the 5-20 elements that carry the slide's structure:
  - Merge stacked text lines of one block into ONE element (title, subtitle, text, bullets, quote or label).
  - Ignore tiny decoration, background texture and page furniture (page numbers, footers, small logos in a corner).
  - Keep repeated shapes (cards, steps, icons in a row): one element each, so the repetition shows.
  - Keep the connectors and arrows that form the composition; give connectors "from" and "to" when they join two elements.
  - Keep the insight device (the big number, highlighted bar, callout, contrast or takeaway line the slide is built
    around) and mark it emphasis "hero" or "strong". Use kind takeaway for the one-line conclusion, framed or not.
  - Containers group content: band (full-width horizontal strip), strip (vertical band), panel (large background
    area), card (a box holding content). List containers before the elements inside them and give those elements
    "parent"; containers can nest (a card inside a panel).
  - Charts: kind chart with chart_type, and series / categories counted from the picture. Tables: kind table with
    rows / cols counted from the grid.
  - shape is the outline you see: none for unframed text, rect, round_rect, ellipse, chevron, arrow_*, triangle,
    diamond, line, or polygon (with points).

Hard rules:
  - No words from the slide and no fields other than the ones above: the mockup's only text is a bracket label made
    from "kind" (and chart_type), e.g. [title], [text], [bar chart].
  - Write only the JSON file, nothing else.
